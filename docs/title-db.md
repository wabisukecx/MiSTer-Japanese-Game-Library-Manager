# 日本語名DBの書き出しとマージ

ライブラリで集めたROM名と日本語名の対応を、将来再利用できるJSONとして保存します。対象は登録済みROMの候補・確定名・判断履歴です。ダウンロードした各DBのカタログ全体は出力しません。

## CLIから使う

書き出し・マージはCLIで実行します。GUIには専用メニューを設けていません。

```powershell
mister-jp-library export-title-db --out work/title-db/titles.json
mister-jp-library export-title-db --system NES --confirmed-only --out work/title-db/nes.json
mister-jp-library export-title-db --hash-roms --out work/title-db/titles-with-hashes.json
mister-jp-library merge-title-db work/title-db/first.json work/title-db/second.json --out work/title-db/merged.json
```

通常の出力ではROM名だけを対応付けの基準にします。`--hash-roms` は登録済みのローカルROMを読み、SHA-256を追加します。ZIPは内部ROMを対象とし、CHDはCHDファイル自体のバイト列を対象とします。CHDと元のBIN/CUE、バイト順やヘッダーの違うROMが同じハッシュになるとは限りません。登録元ROMが見つからない・読めない場合は出力を中止します。

マージはオフラインで実行でき、ライブラリDBも作成・更新しません。中断した書き出し・マージは、データの構築が終わるまで出力ファイルを作成しません。

## マージ規則

- 機種IDが一致し、同じSHA-256、またはSHA-256を持たず同じSHA-1を持つレコードをまとめます。
- 強いハッシュがなければ機種IDと拡張子・地域・Revを含むROM名でまとめます。CRC32がある場合はそれも一致することが条件です。
- ハッシュ付きとハッシュなし、異なるハッシュ、異なる機種は自動で同一視しません。名前の類似だけで地域・Rev違いを統合しません。
- 名前の別名、候補、出典、利用条件、判断履歴は重複を除いて蓄積します。
- 複数の確定名が競合しても選び直しません。原表記を残し、`confirmation_conflict` に記録します。全角・半角と空白だけの差は競合に数えません。
- 候補の競合は `candidate_conflict`、いずれかの競合があるレコードは `needs_review` として出力します。多数決は行いません。

同じファイルを繰り返しマージしても、同じ候補や同じ履歴は重複しません。取得日などが異なる根拠は別の観測として残します。同一の強いハッシュに対して他のハッシュ情報が矛盾する入力は、自動修正せずエラーにします。
マージは過去の判断を集める処理です。解除履歴を含む新しいファイルを追加しても、過去の入力に記録された確定名は削除しません。日時を根拠に他の入力の判断を取り消すこともありません。

## JSONの形式と履歴

形式識別子は `format: "mister-jp-title-db"`、`schema_version: 1` です。

| フィールド | 内容 |
|---|---|
| created_at | 出力したUTC日時 |
| licenses | 候補・履歴の利用条件の一覧。出力全体の単一ライセンスではありません |
| entries[].entry_id | 機種と同定情報から生成する識別子 |
| entries[].system | 本ツールで対応するMiSTer機種ID |
| entries[].rom_names | 元のROMファイル名と、同一内容として集めた別名 |
| entries[].hashes | 任意のSHA-256等。通常のGUI出力では空 |
| entries[].candidates | 元表記、照合根拠、出典、ライセンス、取得日時など |
| entries[].confirmed_titles | 各入力で利用者が確定していた原表記。競合時も複数保持 |
| entries[].history | 確定・解除・更新・一括承諾の日時、変更前後の名前、その時点の候補 |

判断履歴は記録された操作だけを出力します。履歴のない確定済みの名前も出力しますが、日時や根拠は補いません。履歴は名前の更新と同じSQLiteトランザクションに保存し、失敗した承諾は履歴も残しません。

PC内のROM・画像のパス、ライブラリ名、接続先や認証設定は出力しません。出典URLのユーザー認証情報と一般的な認証クエリーは除去し、ローカルの絶対パスやFTP等で指定された出典は `local-source` として記録します。

## 利用範囲

現時点ではローカルでの蓄積・ファイル間の統合用です。JSONをライブラリへ戻す機能、外部DBへの投稿、公開サーバーへのアップロードは行いません。MiSTer向け別名ファイルの反映は転送フローを使います。汎用の `export` コマンドとは別機能です。

元のDBの出典とライセンスは各レコードに残します。ユーザーの判断や統合結果にGPL・CC等の公開ライセンスを自動付与しません。再配布する場合は、出力された帰属・利用条件と元提供者の条件を確認してください。
