# GUIの操作

初めて使う場合は[初回セットアップ](setup.md)を先に進めてください。標準の画像取得手順では、MiSTerへのConsole Mode導入とFTP接続、PCのSkraper準備、SkraperでのScreenScraperユーザー認証を済ませておきます。

## 起動

プロジェクトのルートで実行します。

```powershell
.\.venv\Scripts\mister-jp-library.exe gui
```

別のDBを使う場合は、サブコマンドより前に `--db` を指定します。

```powershell
.\.venv\Scripts\mister-jp-library.exe --db work/another.sqlite3 gui
```

## 1. PCのROMを登録する

「PCのROMを登録」でライブラリ名、機種、PCフォルダー、MiSTerの保存先を指定します。
ライブラリ名はPC内の管理単位です。接続先のIPとは別なので、転送時にも実機の接続先を確認してください。

登録はサブフォルダーも探索します。media・ドットで始まるフォルダーは除外し、同名ROMは大文字小文字を無視して最初の1本を採用します。
転送先は機種ルート直下へ集約され、PCのフォルダー階層は再現しません。

ゲームボーイとゲームボーイカラーは同じフォルダーから登録できます。ROMの拡張子、ZIPでは内部ROMの拡張子で機種を振り分けます。
共通の `.bin` を使う機種は、事前にPC側のフォルダーを分けてください。[対応機種](systems.md)

既定では登録後に日本語名を照合します。照合が失敗しても登録済みのROMは残ります。詳細機能から再照合できます。
再登録は確定済みの名前と画像選択を保持します。

## 2. 画像を取得して取り込む

1. ライブラリと機種を1つに絞ります。ゲームボーイとゲームボーイカラーも別々に操作します。
2. 「Skraperで画像取得・取り込み」を開きます。
3. `SkraperUI.exe` があるフォルダーを指定してSkraperを起動します。
4. Skraper側でScreenScraperへのログインを確認し、ROMフォルダー・画像出力先を設定して取得を実行します。
5. 管理ツールへ戻り、画像出力先を確認して「取得画像を取り込む」を実行します。
6. 対応するROM・画像・地域を確認し、候補として登録します。

Skraperの設定ファイルからROMと画像のパスを検出できます。取得処理自体はSkraper側で操作します。
取り込み対象はPNGで、基本名がROM名に完全一致する画像を対応付けます。同名画像・ROMが複数あれば自動対応しません。

画像は `work/images/<機種>/` にコピーされます。取り込み後にSkraper側を整理しても管理コピーは残ります。
同じ画像の内容が変わった場合は選択を解除します。同じ内容の再取り込みでは選択を保持します。
地域のJP指定は記録用で、画像が日本版であるかは表示を見て確認します。

## 3. 名前・画像を確認する

日本語名候補には照合理由と出典が表示されます。候補を選ぶか手入力して確定します。
利用可能なDBをすべて照合し、全角・半角と空白だけの違いは1つの候補にまとめます。根拠欄には元の表記と各出典・利用条件を表示し、スクロールして比較できます。ROM内容が一致した候補は先頭に表示しますが、記号や副題などが異なる場合は個別に選んでください。多数決や表記の自動確定は行いません。
score 1はROMの内容一致に限らず、ROM名の一致にも使われます。作品の正しさを表す確率ではありません。

画像は内容と文字の向きを確認して採用します。回転補正は90度単位で別ファイルとして保存し、元画像を残します。
補正元が更新されたコピーは再選択・承諾・転送を拒否するため、新しい元画像から作り直してください。

チェックしたゲームは「一括承諾」でまとめて確認できます。名前は全角・半角と空白の違いをまとめて候補が1種類だけで、score 1の根拠を含む場合に対象となります。異なる表記が1つでも残る名前は対象外です。画像は有効な末端候補が1つの場合に対象となります。
複数候補は個別に確認します。承諾はPC内の保存で、この操作だけではMiSTerへ転送しません。

## 4. MiSTerへまとめて転送する

1. ライブラリと機種を1つに絞ります。
2. 対象ゲームをチェックします。チェックがなければ表示中の全件が対象です。
3. 「MiSTerへまとめて転送」を開き、ROM・画像・日本語名の対象を選びます。
4. 必要なら「既存ROMもPCと内容照合する」を選びます。不一致は書き込み前に停止します。
5. 接続先IP・ユーザー・パスワードを入力し、確認した内容を転送します。

既存ROMは上書きしません。画像はROMフォルダーのmedia、日本語名は実機設定の別名ファイルへ反映します。
画像だけ・名前だけ・ROMだけも選べます。機種ルート直下のみが対象で、子フォルダーのゲームは転送できません。

完了後にConsole Modeへ入り直し、名前・画像・起動を確認します。画像の最適化が必要な場合はConsole Mode側で行います。
中断や失敗時の扱いは[転送と復旧](recovery.md)を参照してください。

## 詳細機能

機種一覧はコンソール、ハンドヘルドの順に分け、その中をメーカー別・機種の発売順に並べます。機種フィルター、PCのROM登録、実機ROM一覧取得で同じ順序を使います。分類見出しは選択できません。バーチャルボーイは据置き型としてコンソールに分類しています。

| 操作 | 用途 |
|---|---|
| 日本語名をDBで再照合 | 未確定の名前候補を更新 |
| 最新のDBを取得して確定済みと比較 | 最新候補と確定名の差を表示。選択した更新だけ適用 |
| 日本語名DBを書き出す（JSON） | チェックしたROM、未チェックなら表示中ROMの候補・確定名・出典・判断履歴を出力 |
| 日本語名DBのJSONをマージ | 複数JSONを統合し、競合を保持して新しいJSONに保存 |
| 実機のROM一覧を取得 | ROM内容を取得せず、実機のファイル名を登録 |
| 日本語タイトル設定 | 実機の別名設定・日本語フォントの確認と名前単独転送 |
| 転送記録から復旧 | v2形式の一括転送記録から転送前の状態へ戻す |
| 保存済みの画像フォルダーを取り込む | 取得済みPNGを候補として登録 |

一覧の再読み込みでは欠落した画像参照を整理します。管理画像は手作業で移動・削除せず、保存場所は[データ管理](data.md)を確認してください。
