# GUIの操作

初めて使う場合は[初回セットアップ](setup.md)を先に進めてください。標準の画像取得手順では、MiSTerへのConsole Mode導入とFTP接続、PCのSkraper準備、SkraperでのScreenScraperユーザー認証を済ませておきます。

## 起動

プロジェクトのルートで実行します。

```powershell
.\.venv\Scripts\mister-jp-library.exe gui
```

別のDBを使う場合は、サブコマンドより前に `--db` を指定します。

```powershell
.\.venv\Scripts\mister-jp-library.exe --db work/another.sqlite3 gui
```

## 1. PCのROMを登録する

「PCのROMを登録」で機種、PCフォルダー、MiSTerの保存先を指定し、「ROMを一覧に追加」を押します。この操作はフォルダー設定を保存するだけでなく、ROMを検索して管理画面の一覧へ追加します。MiSTerへの転送は、追加後にゲームを選んで行います。
初回起動時にプロジェクト内の `work/Roms/` と、機種IDごとのサブフォルダー（`NES`、`SNES`、`NGP`、`NGPC` など）を自動作成します。ROMを各フォルダーへ置き、登録してください。フォルダーの作成だけではROMを登録しません。
PCのROMフォルダー欄には、保存済みの指定があればそのパス、なければ `work/Roms/<機種ID>/` を表示します。「参照」やパスの直接入力で別のフォルダーも指定できます。別DBで起動しても既定フォルダーはこのプロジェクトの `work/Roms/` です。再起動時も既存ファイルを保持します。
転送先が1つの機種はパスだけを表示します。メガドライブなど複数の対応先がある機種では、転送先を選択できます。
ライブラリ名の入力・切り替えは不要です。接続先IPは転送時に指定します。

登録はサブフォルダーも探索します。`media`・ドットで始まるフォルダーは検索から除外します。異なるサブフォルダーに同じファイル名のROMがある場合は、大文字小文字を無視して最初に見つかった1本を登録します。
転送先は機種ルート直下へ集約され、PCのフォルダー階層は再現しません。
ZIPは選択機種のROMが1本だけ入っているものを扱えます。ZIP内のサブフォルダーも検索し、転送時はZIPファイルのまま送ります。

ゲームボーイとゲームボーイカラーは同じフォルダーから登録できます。ROMの拡張子、ZIPでは内部ROMの拡張子で機種を振り分けます。
ネオジオポケットとカラーは、機種をそれぞれ選んでPCのROMフォルダーを登録します。PCフォルダーとSkraper設定は別々に保持し、MiSTerへの転送先はどちらも `/media/fat/games/NGPC` に固定します。
共通の `.bin` を使う機種は、事前にPC側のフォルダーを分けてください。[対応機種](systems.md)

既定では登録後に日本語名を照合します。照合が失敗しても登録済みのROMは残ります。同じフォルダーを再登録して照合をやり直せます。
再登録は確定済みの名前と画像選択を保持します。
起動・再読み込み時に、現在設定したPCフォルダー内に実在する登録済みROMだけを一覧へ表示します。ROMがない場合は一覧から外しますが、ファイル名・日本語名・画像の対応や判断履歴はDBに保持します。
同じ機種・ファイル名のROMを設定フォルダーへ置いて「再読み込み」を実行すると、保存済みの名前・画像を引き継いで再表示します。移動後のPCパスも自動更新します。初めて扱うROMは「ROMを一覧に追加」で登録してください。実機から取得したROM一覧は、PCのROMが未登録でも表示します。転送前にも実ファイルを再確認します。

## 2. 画像を取得して取り込む

1. 機種を1つに絞ります。ゲームボーイとゲームボーイカラーも別々に操作します。
2. 「Skraperで画像取得・取り込み」を開きます。
3. `SkraperUI.exe` があるフォルダーを指定してSkraperを起動します。
4. Skraper側でScreenScraperへのログインを確認し、ROMフォルダー・画像出力先を設定して取得を実行します。
5. 管理ツールへ戻り、画像出力先を確認して「取得画像を取り込む」を実行します。
6. 対応するROM・画像・地域を確認し、候補として登録します。

Skraperの設定ファイルからROMと画像のパスを検出できます。取得処理自体はSkraper側で操作します。
取り込み対象はPNGで、基本名がROM名に完全一致する画像を対応付けます。同名画像・ROMが複数あれば自動対応しません。

画像は `work/images/<機種>/` にコピーされます。取り込み後にSkraper側を整理しても管理コピーは残ります。
同じ画像の内容が変わった場合は選択を解除します。同じ内容の再取り込みでは選択を保持します。
画像地域の選択は、今回取り込む画像候補すべてに付ける記録用の値です。選択すると記録予定の地域と件数を表示し、「候補として取り込む」を押した時点で保存します。画像の差し替えや一覧の絞り込みは行いません。日本版の画像が必要な場合はSkraper側で地域を設定して再取得してください。画像が日本版であるかは表示を見て確認します。

## 名前・画像を確認する

ゲームを選択すると、右側の同じパネルに日本語タイトルとパッケージ画像を表示します。タブを切り替える必要はありません。照合根拠や画像の出典は「候補の根拠・画像の出典」を開いて確認できます。
出典欄は閲覧専用です。日本語タイトルを選択・入力し、必要なら画像の向きを変えて「名前・画像を保存」を押すと、タイトルの確定と画像の採用・回転補正をまとめて保存します。タイトルや画像の片方だけでも保存できます。

日本語名候補には照合理由と出典が表示されます。候補を選ぶか手入力して確定します。
未確定で候補がある場合は、先頭候補を選択し、入力欄と根拠を表示します。保存するまでは確定しません。確定済みの名前がある場合はその内容を優先し、候補がない場合は手入力になります。
利用可能なDBをすべて照合し、全角・半角と空白だけの違いは1つの候補にまとめます。根拠欄には元の表記と各出典・利用条件を表示し、スクロールして比較できます。ROM内容が一致した候補は先頭に表示しますが、記号や副題などが異なる場合は個別に選んでください。多数決や表記の自動確定は行いません。
score 1はROMの内容一致に限らず、ROM名の一致にも使われます。作品の正しさを表す確率ではありません。

画像は内容と文字の向きを確認して採用します。回転補正は90度単位で別ファイルとして保存し、元画像を残します。
画像の選択欄は表示しません。保存済みの画像を優先して自動表示し、その画像を回転・保存できます。取得元・地域・補正情報は出典欄で確認できます。
補正元が更新されたコピーは再選択・承諾・転送を拒否するため、新しい元画像から作り直してください。

名前・画像の調整はゲームを選択して右側で行います。「名前・画像を保存」はPC内の保存です。チェックボックスは転送対象の選択に使います。
転送画面では対象ゲームのサムネイルと表示名をまとめて確認できます。名前が単一候補なら、タイトル名だけの一致も根拠を表示して確認対象にします。異なる表記が残る名前は自動で選びません。画像は選択済みを保持し、未選択なら有効な末端候補が1つの場合に表示します。回転などの調整がなければ、先に個別保存する必要はありません。

## 3. MiSTerへ転送する

1. 機種を1つに絞ります。
2. 対象ゲームをチェックします。未チェックの場合は転送せず、全件へ対象を広げません。
3. 「3 · MiSTerへ転送」を開き、サムネイルと表示名を確認します。通常は利用可能なROM・画像・名前をまとめて送るため、転送種別を選ぶ必要はありません。
4. 接続先IP・ユーザー・パスワードを入力し、「この内容でMiSTerへ転送」を押します。初めて採用する名前・画像も、この決定でローカルに保存してから転送します。確認後に候補やファイルが変わった場合は転送前に停止します。失敗・中断時もゲームのチェックは保持します。
5. 転送種別の変更、既存ROMの内容照合、パスワード保存は、必要な場合だけ「詳細設定」を開きます。内容照合を有効にすると、不一致は書き込み前に停止します。IPとユーザーは記憶され、パスワード保存はWindowsのアカウントで暗号化します。保存のチェックを外して実行すると保存済みパスワードは削除されます。

既存ROMは上書きしません。画像はROMフォルダーのmedia、日本語名は実機設定の別名ファイルへ反映します。
画像や日本語名がないゲームも転送します。日本語名を追加しない場合は実機側の表示設定に従い、通常はROM名のまま表示します。今回送らない画像・別名を実機から削除することはありません。
「詳細設定」では画像だけ・名前だけ・ROMだけの転送も選べます。機種ルート直下のみが対象で、子フォルダーのゲームは転送できません。

完了後にConsole Modeへ入り直し、名前・画像・起動を確認します。画像の最適化が必要な場合はConsole Mode側で行います。
中断や失敗時の扱いは[転送と復旧](recovery.md)を参照してください。

## 機種一覧と保守操作

機種一覧はコンソール、ハンドヘルドの順に分け、その中をメーカー別・機種の発売順に並べます。分類見出しは選択できません。バーチャルボーイは据置き型としてコンソールに分類しています。

通常画面に保守用メニューはありません。日本語名DBの書き出し・マージ、実機ROM一覧の取得などは[CLI](cli.md)を使います。復旧が必要な転送記録があるときだけ、画面上部に「転送を復旧」を表示します。再起動後も未完了の記録を確認します。[転送と復旧](recovery.md)

一覧の再読み込みでは欠落した画像参照を整理します。管理画像は手作業で移動・削除せず、保存場所は[データ管理](data.md)を確認してください。
