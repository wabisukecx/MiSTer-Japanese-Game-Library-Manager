# 転送と復旧

## 転送する内容

| 種別 | 処理 |
|---|---|
| ROM | 同名既存ファイルがない場合だけ追加。既存ROMは上書きしない |
| 画像 | `<ROMルート>/media/<ROM基本名>.png` を追加・更新 |
| 日本語名 | 実機config.iniのGLOBAL.aliasPathが指定するtxtへ統合 |

転送は1実機・1機種・同一ROMルートが対象です。GUIの画面でROM・画像・名前をそれぞれ選べます。
FTPはポート21、タイムアウト20秒を使います。スキャン用CLIのport・timeoutオプションとは独立しています。

## 確認とバックアップ

転送前にローカルファイルと計画のハッシュを再検査します。
「既存ROMもPCと内容照合する」を選ぶと、実機の既存ROMも読み戻し、サイズとSHA-256を比較します。
不一致は画像・名前を書き込む前に停止します。ZIPは転送するZIP本体を比較するため、再圧縮したものも不一致になり得ます。

名前を送る場合は別名パスと日本語フォントを確認し、実機のgames配下を再帰検査します。
承認対象以外の同名基本名があれば停止します。media・ドットで始まる項目・games以外の独自ルートは検査対象外です。
取得できない一覧や不明な種類の項目があれば、衝突を確認できないものとして停止します。

既存画像と別名は、全対象をPCにバックアップしてから書き込みます。
不足ROM → 画像 → 日本語名の順に、一時ファイルへ転送・読み戻し照合・renameによる公開・公開後の照合を行います。
既存ファイルは実機にもバックアップを残します。別名の衝突と転送先の変更も公開前に再検査します。

## 転送記録

一括転送の記録は、DBと同じディレクトリの `transfer-backups/<実行ID>/transfer.json` に保存します。
既定では `work/transfer-backups/` です。PC側の元データ、実機バックアップ先、一時パス、ハッシュ、処理段階を記録します。
パスワードは記録しません。

| 状態 | 意味 |
|---|---|
| verified | 全対象を転送・照合済み |
| rolled_back | 中断・失敗後、反映済みの対象を復旧済み |
| rollback_failed | 復旧できていない対象がある |

失敗・中断の区別はoutcome、個別ファイルの状態はitemsに残ります。GUIの完了表示とあわせて確認してください。

## 自動復旧

失敗・中断時は反映済みファイルを逆順で戻します。
既存データは実機バックアップから復元し、新規追加分は `.mister-jp-rollback-<実行ID>` を付けて退避します。
作成した空フォルダーや一時ファイルは残る場合があります。

転送後に外部で変更されたファイルは上書きしません。通信断・競合・バックアップ不一致は復旧未完了として記録します。
FTP上の一括トランザクションではないため、同じ対象を別アプリから同時に変更しないでください。

## 記録から復旧を再実行する

1. 実機の接続と、必要なバックアップが残っていることを確認します。
2. 未完了の復旧や中断された書き込みがある場合、GUI上部に表示される「転送を復旧」を開きます。再起動後も未完了の記録から表示します。
3. 該当するtransfer.jsonを選び、対象ファイルと実機IPを確認します。
4. FTP認証情報を入力し、復旧を実行します。
5. 結果を確認し、Console Modeで表示とゲーム起動を確認します。

CLIでも同じ復旧処理を使えます。

```powershell
mister-jp-library recover-transfer work/transfer-backups/<実行ID>/transfer.json --host 192.0.2.10 --user root
```

記録と同じIPを指定します。復旧済みの対象を再実行しても再変更しません。正常完了した転送の記録から元へ戻すこともできます。

自動復旧の対象は `mister-jp-transfer/v2` 形式の一括転送記録です。
v2形式以外の記録は対象外ですが、元データと記録は手動復旧の資料として保持してください。
復旧が完了するまで、PC・実機のバックアップを移動・削除しないでください。
